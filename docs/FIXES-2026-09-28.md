### D7 — JS syntax gate (kernel done, tests pending)
New `kernel/jscheck.py`, hooked into `validate_html()` (so `_app_generate` → `repair_html`,
`generate_page` and `h_app_repair` all see it): every classic inline `<script>` is compiled with
QuickJS's `qjsc -c -o /dev/null` (Debian trixie package `quickjs` 2025-04-26, ~2 MB) — a real ES2023
parser, no node. Issue text = script number, DOCUMENT line/column, the parser message and the offending
line. Then all scripts concatenated once (the browser's shared global lexical scope: `let x` twice is a
SyntaxError). Choice justified in the module docstring: trixie's only pure-Python parser
(`python3-calmjs.parse`) is ES5-only and would flag valid modern code; the browser-side `new Function`
path is what the shell already does after delivery. Verified 2026-09-28 in a trixie container: modern
syntax (class fields/private/static blocks, `?.` `??=`, BigInt, regex named groups/lookbehind, for-await,
dynamic import, nested templates, Annex B `<!--`, `/]/`, legacy octal, ASI) passes; the qwen35 pattern
`async x: async function()`, top-level await/return, unterminated strings and truncated files fail with
line:col; Ubuntu noble's quickjs (2021) is too old and is refused (version check ≥ 2024-01-01). Known
divergence — V8's regex `v` flag — is on an ignore list (regex complaints are never reported).
`node --check` is the fallback checker on developer machines; nothing installed → gate off, one startup
line, `/api/status.js_gate`. `VIBEOS_JS_CHECK=off|<path>`.
Appliance packaging: `quickjs` added to `iso/config/package-lists/kairos.list.chroot` and
`scripts/build-image.sh` (pending, see the A3 block).
