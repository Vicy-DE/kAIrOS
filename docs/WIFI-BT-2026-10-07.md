# WiFi & Bluetooth system API — R78 (v7.5-1 hotfix)

Owner, 2026-10-07: *"think about wifi and bluetooth functions via simple system api (the things the
settings could work with)"*, then: into the v7.5-1 hotfix, **nothing prebaked** — no WiFi profile of
the host is copied into the image or onto the stick (the build's `OpenAP` from `iso/secrets/wifi.env`
stays); joining any other network happens in the OS. Requirement: `docs/REQUIREMENTS.md` R78. Work log
and step results: `vibeos-cuda-next/results/v75-wifi-bt/STATUS.md` (outside the repo).

## Why

- The stick never got online in three runs: the laptop travels, only `OpenAP` was baked and was out of
  range (`Neuland_5G` was visible). AX210 WiFi (8086:2725, iwlwifi) and BT (USB 8087:0032) load fine.
- Defects of the R38/R55 API: `status().ssid` was the NetworkManager profile NAME (host proof: profile
  `ffm.freifunk.net`, in-use SSID `owe.ffm.freifunk.net`) so disconnect/forget by a scanned SSID failed;
  OWE ("Enhanced Open", Freifunk) reported a security and generated apps asked for a password; nmcli's
  terse `\:` escapes were split; Bluetooth `pair` never trusted (no reconnect after a reboot) and had no
  agent (passkey devices could not pair); `scan` returned every cached device; `off` was a bluez
  `power off` that AutoEnable undid at boot; the image had no NetworkManager connectivity check, so a
  captive portal (WIFIonICE, hotels) looked online; `knowledge.online()` lagged 30 s behind a connect.

## API

Additive — every existing call and field keeps its shape (`bluetooth.status().connected` stays a list
of names: objects would print `[object Object]` in apps generated before R78). Full reference:
`docs/API.md` ("WiFi connect — full reference", "Bluetooth & airplane mode [R78]"); the sheet the coder
LLM gets: `docs/api/network.md`; recipes: `docs/wiki/wifi-manager.md`, `docs/wiki/bluetooth-manager.md`.

| call | answer |
|---|---|
| `vibe.hw.wifi.status()` | `{available, enabled, connected, ssid (REAL SSID), signal, bars 0-4, ip, connectivity full\|portal\|limited\|none\|unknown, device, devices, starting?, connecting?, reason?}` |
| `vibe.hw.wifi.scan()` / `scan({fresh:true})` | `{networks:[{ssid, signal, bars, band 2.4\|5\|6, security, needs none\|password\|login, saved, in_use}], age_s}` |
| `vibe.hw.wifi.connect(ssid, password?)` | `{ok, error wrong_password\|needs_password\|not_in_range\|timeout\|unsupported\|ssid_required\|failed, detail, connectivity}` |
| `vibe.hw.wifi.disconnect()` / `.forget(ssid)` / `.saved()` | `{ok}` / `{ok, deleted}` / `{networks:[{ssid, auto, last_used}]}` |
| `vibe.hw.wifi.on()` / `.off()` / `.signin()` | `{ok, enabled}` / `{ok, url, portal}` |
| `vibe.hw.bluetooth.status()` | `{available, powered, blocked, connected:[names], devices:[{mac, name, kind, paired, trusted, connected, battery}], pairing?}` |
| `vibe.hw.bluetooth.scan()` | `{devices:[{mac, name, kind, rssi, paired:false}], seconds}` — only this scan's named, unpaired devices |
| `vibe.hw.bluetooth.pair(mac)` | `{ok, error enter_code\|auth_failed\|not_in_range\|timeout\|busy\|bad_mac, code, name, kind, trusted, connected, sound?}` |
| `vibe.hw.bluetooth.on()` / `.off()` | unblock + power on / rfkill block |
| `vibe.hw.airplane.get()` / `.set(bool)` | `{available, airplane, wifi_enabled, bluetooth_blocked}` |

The host pages (`shell/shell.js`, `shell/bench/host.js`) used to throw on every answer with an `error`
field; WiFi / Bluetooth / airplane answers that carry a boolean `ok` now resolve, so the codes reach the
app (an unknown op or a 403 still rejects). R66: `saved`, `scan`, `status`, `get` are reads; every other
op changes the machine and needs loopback or the token.

## Design notes (kernel/hw.py)

- nmcli always with `-t -e yes`; `_nm_split` undoes `\:` / `\\`. The SSID of the active connection comes
  from the profile's `802-11-wireless.ssid` (looked up per UUID), never from the profile name.
- `needs` from nmcli's SECURITY: `""`/`--`/`OWE`/`OWE-TM` → none, WPA*/SAE/WEP → password, 802.1X → login.
  OWE transition mode: the open SSID + a hidden OWE BSS that shows its own name once associated — that
  twin is folded into the joined SSID instead of a second list entry.
- connect: a saved profile of the SSID is reused (`con up`); a new password is written into it and the old
  one restored when the join fails; otherwise `dev wifi connect` — and the profile a failed join left is
  deleted. A failed join takes the device off its network: NetworkManager's autoconnect normally brings
  it back; if not within `RESTORE_DELAY` (4 s) and no newer connect started, kAIrOS re-activates it.
  The password is replaced by `•••` in `detail` and never printed.
- A radio-state cache (2 s, unavailable 10 s, saved profiles 30 s) — every write clears it and calls
  `hw.ON_CHANGE` (the kernel resets `knowledge.online()`'s cache there).
- Bluetooth: ONE long-lived interactive `bluetoothctl` on a pty (stdlib `pty`), registered as the
  KeyboardDisplay default agent; prompts are answered only while a `pair()` runs (numeric comparison →
  yes, a displayed passkey → `code`, anything else → no). `pair` → `trust` → `connect`; an audio device's
  PipeWire sink is looked up, and made the default if WirePlumber has not done it (`sound.default_by`).
- Without a controller in `/sys/class/bluetooth` (a VM, a desktop) Bluetooth answers "no Bluetooth adapter
  found" without spawning bluetoothctl (which waits for a bluetoothd that never starts: 6 s per status).
  `connect()` waits up to 12 s while the WiFi device is still `starting`; a disconnect/forget/radio/airplane
  write bumps the join generation, so a pending re-join never undoes it.
- Airplane: `nmcli radio all off` + `rfkill block bluetooth`; off: `rfkill unblock wlan`, `nmcli radio all
  on`, Bluetooth unblock + power on. NetworkManager keeps the WiFi radio state
  (`/var/lib/NetworkManager/NetworkManager.state`), systemd-rfkill the Bluetooth block.
- Sign-in: `signin()` fetches the connectivity URI without following redirects (a portal's 302 Location
  is the login page), writes it to `/run/kairos/open-url`; `.xinitrc` (user kairos) opens
  `chromium --app=<url> --user-data-dir=/tmp/kairos-signin` and removes the flag; a watcher re-checks
  connectivity every 10 s and writes `/run/kairos/close-url` once online / off the network / after 15 min.
- `etc/NetworkManager/conf.d/20-kairos-connectivity.conf`: `uri=http://network-test.debian.org/nm`,
  `response=NetworkManager is online`, `interval=300` — the endpoint of Debian's
  `network-manager-config-connectivity-debian` (1.52.1, verified 2026-10-07: 200, 25 B body).
