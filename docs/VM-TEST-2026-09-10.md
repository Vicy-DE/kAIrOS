# Full end-to-end VM test — 2026-09-10 (independent verification run)

Scope: boot the shipped v6 appliance image on the real RTX 4070 via VFIO, deploy the
~2 days of unverified work (boot diagnostics R51, reworked boot animation, R66 network
hardening, engine selection, multiscreen, cache/console/ESP/initramfs changes), reboot,
and judge what actually works — including two deliberate failures to prove the
diagnostics answer "why did this run fail?".

Verifier role: no product code was modified. Everything below was changed either on the
VM's **qcow2 overlay only** (deliberate breakage + restore) or in the **test rig glue**
(`pod/testrig/sync-guest.sh`). The backing image `kairos-hwtest-4070-v6.img` is byte-for-byte
untouched (mtime still Jul 16 07:55).

## 5. Phase 4 — deliberate failures

### 5a. Break X (`chmod -x /usr/bin/Xorg /usr/lib/xorg/Xorg`) + reboot

The first reboot produced something **worse and unplanned**, and it is the most important
finding of the run: `getty@tty1.service` never started at all.

```
systemd[1]: getty.target: Found ordering cycle on getty@tty1.service/start
systemd[1]: getty.target: Job getty@tty1.service/start deleted to break ordering cycle starting with getty.target/start
```

Result: no login, no startx, no X, no kiosk — **and `systemctl --failed` was EMPTY**. See **D7**.

The diagnostics handled it correctly:

```

 PASS boot_history  attempt #2; early breadcrumb ran (root + EFI partition mounted)
 PASS boot_target   graphical.target reached (system: running)

 PASS rootfs_grow   root grown on first boot (108G total, 59G free)
 PASS gpu_driver    0000:00:05.0 0x1af4 driver=virtio-pci boot_vga=1; 0000:00:06.0 NVIDIA driver=nvidia boot_vga=0;
 PASS firmware      no firmware load failures in dmesg
 WARN modules       module load failures: nvidia: module verification failed: signature and/or required key missing - tainting kernel;
 FAIL xorg          X never attempted (tty1 autologin -> startx did not run) — check getty@tty1 in the journal

(`kairos-x11vnc` is the rig's own unit, not product.)

A second reboot let `getty@tty1` start (the cycle-break picked `getty.target/start`

```

and the X LOG section carried the exact root cause:
`/usr/bin/X: 10: exec: /usr/lib/xorg/Xorg: Permission denied` / `xinit: server error`.

| Phase-4a criterion | result |
