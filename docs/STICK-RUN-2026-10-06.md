# First stick run of v7 on the target laptop — analysis (2026-10-06)

**Run:** owner booted the Intenso stick (v7, logging patch NOT applied) on the HP laptop (AMD Phoenix
iGPU drives the panel, RTX 4070 Max-Q), boot `#1` 20:28–20:34 CEST, clean power-off. Then rebooted into
Ubuntu; logs pulled read-only with `pod/stick-logs.sh` (`~/kairos/stick-runs/20261006-204151/`).
Evidence: `docs/bench/stick-run-2026-10-06/`.

**Symptom:** no kAIrOS desktop. Boot capture 20:32: `FAIL kiosk: no kiosk Chromium running`
(`xorg PASS` — X held its socket); WiFi not joined.

## Root cause — X stalled on the NVIDIA GPU

| uptime | event |
|---|---|
| 28 s | `nvidia-load.service` starts; `modprobe nvidia` takes 32 s (module + GSP firmware read from the stick) |
| 61 s | nvidia, nvidia_uvm loaded by kairos-gpu-setup (compute-only — the AMD iGPU is boot_vga) — **and nvidia_modeset + nvidia_drm in the same second**, which kairos-gpu-setup never asked for: `nvidia_drm` carries a PCI alias for every NVIDIA GPU (`lspci -k`: "Kernel modules: nouveau, nvidia_drm, nvidia"), udev's coldplug autoloaded it |
| 69.9 s | getty@tty1 → startx; X probes card0 (AMD) |
| 70→116 s | AMDGPU(0) init (45 s — libraries read cold from the stick) |
| 86 s | `[drm] Initialized nvidia-drm … on minor 1` → `/dev/dri/card1` |
| 138→162 s | X adds the 4070 (card1) as a second **GPU screen** via modesetting: glamor 20 s, then `(EE) modeset(G0): Failed to create pixmap`, screen dropped |
| 162 s | X finishes adding input devices — then **no log line for 150 s**; `.xinitrc`'s first X calls (`xset`/`xsetroot`/`xrandr`) never return, x.log has no `xinitrc:` breadcrumb → no openbox, no kiosk |
| 313 s | power-off: session SIGHUP, X segfaults in FreeAllResources while tearing down (consequence) |

The VM tests could not see this: the rig VM has one virtual GPU.

## Other findings
* `serial-getty@ttyS0` failed every 10 s ("failed to get terminal attributes: Input/output error"): the
  default loader entry carries the testrig's `console=ttyS0`, the getty generator adds a getty for it, the
  laptop has no serial port. Journal spam only.
* WiFi: `wpa_supplicant` D-Bus timeout at 20:28:51, recovered 20:29:02; the `OpenAP` profile (autoconnect,
  priority 100) loaded but NetworkManager never attempted it — most likely the AP was not seen. The logs
  cannot say more; the next build's capture lists visible networks + `iw reg get`.
* HP firmware ACPI "BIOS Error … WMID" lines and iwlwifi `iwl-debug-yoyo.bin` misses: harmless.

## Fixes (v7.1 = v7 + the logging work of docs/BOOTLOG-TEST-2026-10-06.md + these)
* `/etc/modprobe.d/kairos-nvidia-hybrid.conf`: `blacklist nvidia_drm`, `blacklist nvidia_modeset` — stops
  alias autoloading only; kairos-gpu-setup's explicit `modprobe nvidia_drm modeset=1` (NVIDIA = boot GPU)
  still works.
* `/etc/X11/xorg.conf.d/10-kairos-single-gpu.conf`: `AutoAddGPU off` — X never adds a second GPU screen
  (defence in depth; outputs wired only to the dGPU stay dark, they would need PRIME).
* `.xinitrc` breadcrumbs before/after its first X calls; kairos-bootlog fails the `xorg` check when X runs
  but the session never reached `xinitrc: displays:` (this run said PASS); WiFi scan/profiles/regdomain in
  the capture.
* Default loader entry: `systemd.getty_auto=0` (no generated serial getty; the hidden serial-debug entry
  keeps it) — build-img.sh + sync-guest.sh.
* `pod/stick-logs.sh` also copies the rootless Xorg logs + /etc/X11 config.

**Verified:** suite 116/116 (new `unit_hybrid_gpu_x_single_gpu`), v7.1 build guest boot PASS 15/15 with
`Option "AutoAddGPU" "off"` read by X and the new breadcrumbs, `vm.sh test` on the raw v7.1 at the stick's
size 16/16. **Not verifiable in the VM:** the NVIDIA part — the next stick run is the test.
