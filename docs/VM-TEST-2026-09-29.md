### 1.1 Blocker: the 4070 cannot be handed to VFIO right now

1. **Steam holds the GPU.** `pod/gpu-to-vfio.sh` (called by `run-gpu-vm.sh`) refuses while any
   process holds `/dev/nvidia0` (`fuser /dev/nvidia0` → exit 1 "GPU busy on the host"). Steam and
   two `steamwebhelper` processes of the owner's desktop session hold it (graphics clients, so
   `--query-compute-apps` is empty — that pre-check does not see them). Closing the owner's Steam
   is not part of the approval for this test, so it was **not** done.
2. **No passwordless sudo in this session** (`sudo -n true` → "interactive authentication is
   required"). `gpu-to-vfio.sh` and `gpu-to-host.sh` run every step through `sudo` when not root
   (stop `nvidia-persistenced`, `rmmod`/`modprobe`, sysfs `driver_override`/`drivers_probe`), so
   `run-gpu-vm.sh` cannot rebind the card from this session as written: the owner runs
   `pod/gpu-to-vfio.sh` / `pod/gpu-to-host.sh` in a terminal (sudo).

Until both are resolved, everything that does not need the GPU is done on a GPU-less rig VM
(same overlay), so the GPU phase can start straight from a synced, rebooted guest.
