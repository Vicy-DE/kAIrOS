### Step 3/4/5 — kernel (done, suite running)
`kernel/prompts.py`: `KREA_EXPAND_SYSTEM` (= bench `krea-expansion.txt` + rule 10 "If the user names
no medium, prefer a realistic photograph.") and `KREA_EXPAND_SYSTEM_ADULT` (= `krea-expansion-18plus.txt`,
byte-identical — verified).
`kernel/server.py`:
- `ENGINE_OF_BINARY` += sd-server; `SD_PORT` 8082, `SD_SERVER_LOAD_TIMEOUT` 900 s.
- settings `image_expand` (auto|on|off, default auto); `IMAGE_MODEL_KEYS` += `chroma`.
- expansion: `EXPANDERS`, `EXPAND_SAMPLING` (0.7/64/0.95/0.05/1.05), `expander_for()`,
  `clean_expansion()` (= expand.py clean), `expander_llm_spec()`, `expand_prompts()` — one
  `MM.chat(key="expander:<kind>")` per prompt on the section's text-encoder GGUF under llama-server
  (`-ngl 99 -c 8192 --jinja`, keyed by the file so sections sharing it share the server); a failed
  expansion renders the raw prompt + `IMAGE_PROMPT_HINT`; an expanded prompt gets no hint.
- `ModelManager.chat_payload/chat`: manifest `llm.sampling` merged into every body, per-call
  `sampling` on top (`messages`/`stream` protected).
- `ModelManager.sd_batch(kind, jobs)`: ONE GPU-lock hold, LLM stopped first (swap), then
  `_sd_server_session` (sd-server with the section's argv minus -p/-o, `--listen-ip/--listen-port`,
  readiness = `GET /sdapi/v1/options`, one `POST /sdapi/v1/txt2img {prompt, seed, width, height,
  batch_size 1}` per picture, base64 PNG written atomically, server terminated) or `_sd_cli_each`
  (the old per-picture process) when `bin/sd-server` is absent. `sd_job()` keeps its contract
  (images via `sd_batch`, video via sd-cli `-M vid_gen`).
- `render_images(kind, items, adult, expand)` = expansion (batched) + `sd_batch`; used by
  `/api/image`, the new `POST /api/images` (`prompts:[…]` | `prompt`+`count`, ≤ 12, job result =
  list of URLs, `results` = per-picture records), the `/genimg` batching window
  (`GENIMG_WINDOW` 1.5 s, grouped by model+size, cache/placeholder/limit semantics kept, wait 360 s),
  the forge pre-pass in `render_generated_media` (all a page's pictures in one session) and the
  wallpaper.
- `/api/models`: `chroma` key, per-model `expander`/`licence`/`files`/`size_gb`, `expand` block,
  `sessions` (sd-server|sd-cli); `/api/status.image_sessions`.
- `download_entries`: sha256 verification when the manifest entry carries one.
`shell/shell.js`: `vibe.images(prompts|prompt, count|opts)` in `BRIDGE_SRC` + the `images` dispatcher.
