### N1 — the dialog check reads executable code only (done)
`kernel/jsfix.py`: `dialog_calls(html)` no longer runs a regex over the document text. `executable_js(html)`
collects what a document RUNS — inline `<script>` bodies (classic + module; `src=`/JSON/template types
skipped) and inline `on*="…"` handler attributes (entities decoded; looked for outside script bodies) —
and `dialog_calls_js(code)` walks the module's own tokenizer output (strings, comments, regex bodies and
template-literal TEXT are dropped; a `${…}` expression inside a template is code and is kept; the
tokenizer now keeps a string's body in `Tok.val` so `window["prompt"](` is visible). Only the GLOBAL call
counts: `prompt(`, `confirm(`, `window.`/`self.`/`globalThis.`/`top.`/`parent.`/`frames.` + `?.` forms and
`window["prompt"](`. Not flagged: `ui.prompt()`, `this.confirm()`, `x.window.prompt()`, `promptUser()`,
a method `prompt(q) {…}` / `class … { confirm() {} }`, an app-defined `function prompt()`/`const prompt`,
`.then(prompt)`, and every occurrence in text/attributes/comments/strings. `js_problems()` unchanged.
Tests: `unit_jsfix_await_rewrite` — the re-verification's five false positives + 10 more forms all pass,
13 true-positive forms (incl. the old misses `self.`/`globalThis.`/`top.`/`window?.`/`window["prompt"]`,

### N5 — a failing JS gate is delivered as an explicit verdict, never into the heal loop (done)
Decision: the app stays a `done` (saved as the last version — the user waited minutes for it and can
✨ improve it) but carries `broken` = `gate_verdict(html)` (`kernel/server.py`: `{message, line, problems[:3],
rounds: 2, checker}`, None when every inline script parses or the gate is off). `_app_generate` computes it
after `repair_html` (max_rounds = `GATE_REPAIR_ROUNDS` = 2), streams `// gate: the JavaScript still does not
parse after 2 repair rounds — delivering this version flagged as broken (no automatic self-heal): …`, logs
`[kernel] WARN <app>: delivered broken (JS gate after 2 repairs)`, stores `meta.broken`, and sends it in
`done`; `cached` (reopen) and `fallback` compute it for the version they mount; `POST /api/app/<id>/repair`
answers `{html, broken}` and updates `meta.broken`; `GET /app/<id>` renders host.html with `data-broken`
(JSON, html-escaped; empty when clean). Shell (`shell/shell.js` + `shell/bench/host.js` identically):
`applyGateVerdict(win, data.broken)` right after `mountApp` on done/cached/fallback and after the repair
reply — sets `win.gateBroken`, spends the heal budget (`win.healRounds = HEAL_MAX_ROUNDS`, so the SyntaxError
the document throws goes straight to the banner: no `POST /repair`) and shows `showHealStop()` in its new
gate mode (`⚠ delivered with a syntax error — the OS's 2 repair rounds could not fix it`, the parser message +
document line, "⚕ repair once more" = exactly one manual round as D1, "keep using it"); the toasts say it
instead of "✨ … exists now"/"⚕ app healed"; a clean reply clears the verdict. host.js applies the page's
`data-broken` at load. Before: 3 automatic rounds × ~4.5 min of Gemma 4 on the same unfixable line.
Test: `http_app_js_gate_repairs_before_done` extended — mock persona `[broken-js-unfixable]` (the repair
daemon keeps the broken line): the stream note, `done.broken` (message/line/rounds/checker/problems), the
last version delivered AND saved, `meta.broken`, `cached.broken` on reopen, the repair reply's `broken`,
`data-broken="{…"` on `/app/<id>`; the fixable app: `broken` None everywhere and `data-broken=""`. Static
checks of both host pages in `unit_shell_fixes_static` + `tests/bridge-test.js` (below, with N4).

### N2 — `scripts/build-image.sh` bakes a MIRROR of the list (done)

### Symlink risk — links resolved, dangling links fail (done)
